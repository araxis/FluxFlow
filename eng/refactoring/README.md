# Historical refactoring tools

These scripts and `package-destinations.json` supported the original migration
inventory. The destination map is historical planning input, not the current
package architecture: its proposed Composition/Engine splits and Designer entry
must not be interpreted as outstanding work or current package membership.

Use [../packages.json](../packages.json) for the current package manifest and
[the execution ledger](../../docs/plans/2026-09-12-observability.md) for subsequent
refactors. Retain the original migration inputs for interpreting historical
reports; they are not part of normal build, test or runtime execution.
